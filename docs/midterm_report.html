Predict, Then Choose: A Latent World Model for Language-Guided Robot Pushing

Team: Wasiq Malik · [Teammate name]Code: github.com/humanwhoexplores/RoboJEPA, branch wm/midterm-jepa-vs-direct

AbstractA robot told to “push the cube onto the green square” must choose, among many possible motions, one that makes the instruction true. We test whether a JEPA-style latent world model, which predicts the visual features after each push and checks the prediction against the instruction, chooses better than a classifier that scores each plan directly from the same inputs. A simulated Franka Panda (robosuite) ranks 48 one- and two-push plans per scene; both methods share frozen DINOv2 and MiniLM encoders. We have built the task, data pipeline, both models and a 3-seed evaluation. With 400 training scenes, JEPA selects a successful plan 0.74 ± 0.02 of the time against 0.55 ± 0.05 for the direct classifier, and 0.67 vs 0.42 on two-push plans. On cube positions outside the training range JEPA falls behind (0.38 vs 0.47). Next we test whether a pretrained world model (Meta’s RoboJEPA) and more diverse data close that gap.

2 · Problem Statement and Goal Recap

Vision-language-action models map an image and an instruction straight to motor commands. World-model approaches such as JEPA [1, 2] and DINO-WM [3] instead learn to predict the consequences of an action in a learned feature space and plan by searching over predicted outcomes. Our question is narrow and controlled: given the same inputs, encoders and parameter budget, does explicitly predicting the next state help a robot pick the action that satisfies a language instruction? We study it on a tabletop pushing task where the instruction names a target region either by side (“left”, “right”) or by color (“blue”, “green”). The colors swap between scenes, so color instructions can only be solved by reading the image.

3 · Methods and Implementation to Date

Key design decisions.

  • Task. MuJoCo + robosuite, Franka Panda with an operational-space controller (20 Hz). Success means the cube rests inside the named 13 × 13 cm region after the plan.
  • Candidates are goal-blind. Plans are generated around a noisy cube estimate (σ = 1 cm, standing in for a detector): 8 directions × 3 lengths as single pushes, plus 24 two-push plans. The generator never sees the instruction, so ranking is the whole problem.
  • Shared frozen encoders. DINOv2-small [4] gives 256 patch features of size 384 per image; all-MiniLM-L6-v2 [5] embeds the instruction.
  • JEPA. Predictor: 6-layer transformer over a push token and 256 patch tokens, outputs the change in features (zero-initialized residual head), MSE loss, rolled out push by push. Scorer: 2-layer transformer over instruction + patches, weighted BCE on true end frames. Plan score = scorer(predicted end features).
  • Direct classifier. 6-layer transformer over instruction + 2 push tokens + start patches, weighted BCE. Same width, same data, no future prediction.
  • Oracle. The JEPA scorer applied to the true end features. It is an upper bound that separates prediction error from scoring error.
  • Training and evaluation. Every outcome is labeled against all 4 targets. Fixed step budgets at every data size (predictor and direct 15k, scorer 5k), batch 64, AdamW 3e-4, bf16; checkpoint by validation loss or AUC. Metric: selection success, the share of solvable scene–instruction pairs where the top-ranked plan succeeds (random ≈ 0.10). Ablations: data size, plan length, held-out phrasings, baseline tuning.

Reproducibility. One AMD RX 9070 XT (16 GB, ROCm 7.2), PyTorch 2.13 (ROCm build), MuJoCo 3.3.0, robosuite 1.5.2, HuggingFace Transformers. Collecting all 610 scenes takes ~30 min with 5 workers; a 15k-step predictor run takes ~7 min. python -m robojepa.collect then scripts/run_midterm.sh reproduces every number below.

4 · Preliminary Experiments and Results

Setup. Training: 400 scenes with 16 random plans each (6,400 plans, ~18% successful); validation: 50 scenes. Test: 100 in-distribution scenes and 60 OOD scenes in which the cube starts in a 4 cm strip nearer the camera that no training scene covers; each test scene is paired with 8 instructions (5 training phrasings and 3 held-out paraphrases) and ranked over the same 48 plans.

Interpretation.

  • What worked: predicting first helps when the plan is compositional. A single push only requires learning which direction leads to which region. For a two-push plan, the second push only makes sense given where the first leaves the cube; the predictor rolls forward one push at a time, while the direct classifier has to learn that composition implicitly.
  • Language is not the bottleneck. The oracle picks a working plan 89–99% of the time in every setting, and JEPA keeps its lead on paraphrases it never saw (0.68 vs 0.51). The gap between JEPA and the oracle is world-model error.
  • What didn’t work: OOD generalization. When the cube starts a few centimetres outside the training range, the predictor’s feature error rises by ~80% (Table 2), its ranking AUC drops from 0.95 to 0.84, and the direct classifier wins.
  • Surprise: 4× more data (100 → 400 scenes) improved JEPA in-distribution by 14 points but did not move its OOD score (0.38 → 0.38). More of the same data does not fix extrapolation.
